# Obsidian как второй мозг: хранилище, которое ведёт ИИ-агент

Практическая архитектура для Obsidian: личные записи отделены от рабочего контура агента, данные попадают в дневные заметки автоматически, повторяющиеся процессы копят находки, а каждое утро система формирует три приоритетных дела.

## Хранилище должно работать с информацией каждый день

Обычное хранилище постепенно заполняется заметками, статьями и идеями. Информация остаётся внутри, но редко превращается в решения. Рабочая система устроена иначе: агент собирает данные из подключённых источников, записывает их в дневные заметки, ведёт журнал действий и помогает выбирать задачи на сегодня.

Obsidian удобен для такой системы, потому что хранит материалы в обычных Markdown-файлах. Эти файлы читает человек, Claude Code, Codex и другие агенты. Данные остаются локальными, их можно открыть без специального экспорта и перенести вместе с папкой проекта.

- **человек: ЗАМЕТКИ** - идеи, проекты, задачи, люди и записи по дням
- **агент: ПРОЦЕССЫ** - журнал, сборщики, правила, исследования и находки
- **общий слой: РЕШЕНИЯ** - дневные метрики, аналитика и три дела на сегодня

## Раздели хранилище на две половины

Мысли человека и служебные записи агента должны лежать отдельно. Иначе агент начнёт пересказывать свои выводы рядом с исходными заметками, и происхождение мысли потеряется. Для этого в корне создаются две папки: «Я» и «Агент».

## Я

личное пространство, доступ агенту только на чтение

- **Дни:** ежедневные заметки
- **Задачи:** текущие действия
- **Проекты:** контекст работы
- **Люди:** связи и договорённости
- **Идеи:** собственные мысли

## Агент

рабочее пространство агента

- **Журнал:** что и когда сделано
- **Нужно тебе:** вопросы и три дела
- **Сборщики:** данные из API
- **Процессы:** повторяемая работа
- **Находки:** проверенные выводы

> **правило проекта.** Создавай отдельное хранилище для отдельной системы. Контент, здоровье и бизнес получают свои папки, правила, источники данных и историю изменений.

## Установи навыки Obsidian для агента

Репозиторий kepano/obsidian-skills учит совместимого агента работать с Obsidian Markdown, Bases, JSON Canvas и Obsidian CLI. Официальный репозиторий: https://github.com/kepano/obsidian-skills

## Команды установки в Claude Code

```text
/plugin marketplace add kepano/obsidian-skills
/plugin install obsidian@obsidian-skills
```

После установки открой пустую папку проекта в агентной среде и в Obsidian. Все дальнейшие файлы должны создаваться внутри этой папки. Перед запуском проверь, что в ней нет материалов другого проекта.

## Создай структуру хранилища одним заданием

Промпт создаёт две половины хранилища, короткую карту AGENTS.md, локальные инструкции для папок и шаблон дневной заметки. Сначала агент показывает план и список файлов, затем ждёт подтверждение.

## Промпт для создания второго мозга в Obsidian

```text
Это пустое хранилище Obsidian. Собери в нём локальный бэкенд для ИИ-агентов. Работай по шагам и не выходи за пределы открытой папки.

Сначала выполни read-only проверку: покажи абсолютный путь хранилища, текущее содержимое, поддерживаемые правила доступа в этой агентной среде и точный план изменений. Ничего не создавай до моего подтверждения «НАЧИНАЕМ».

После подтверждения создай две половины.

1. «Я» — моё пространство:
- Я/Дни
- Я/Задачи
- Я/Проекты
- Я/Люди
- Я/Идеи

В папке «Я» агент по умолчанию только читает. Не создавай, не меняй и не удаляй мои файлы. Единственное исключение: проверенные сборщики из «Агент/Сборщики» могут создать сегодняшнюю дневную заметку из утверждённого шаблона, если её ещё нет, а затем обновлять только заранее перечисленные свойства frontmatter. Текст заметки они не меняют.

2. «Агент» — твоё рабочее пространство:
- Агент/Журнал
- Агент/Нужно тебе
- Агент/Сборщики
- Агент/Процессы
- Агент/Исследования
- Агент/Таблицы
- Агент/Шаблоны

В этой половине можно создавать и менять служебные файлы, соблюдая локальные инструкции. Не удаляй существующие файлы без отдельного подтверждения.

3. Создай в корне AGENTS.md длиной не более 60 строк. Это карта хранилища: что лежит в каждой папке, куда смотреть под конкретную задачу и четыре обязательных правила:
- в «Я» ничего не создавать, не менять и не удалять; исключение: проверенный сборщик может создать сегодняшнюю дневную заметку из утверждённого шаблона, если её ещё нет, а затем обновлять только разрешённые поля frontmatter;
- перед работой в папке читать её AGENTS.md;
- после каждой задачи дописывать в «Агент/Журнал/YYYY-MM-DD.md» время, выполненное действие и список затронутых файлов;
- если непонятно, куда положить файл, сначала спросить, новую папку самостоятельно не создавать.

4. В каждой созданной папке положи локальный AGENTS.md длиной до 15 строк: назначение папки, разрешённые действия, запреты и формат файлов. Одно правило должно жить в одном месте. Корневой файл содержит только карту и общие ограничения.

5. Создай «Агент/Шаблоны/День.md». Добавь frontmatter со свойством date: {{date:YYYY-MM-DD}}, затем разделы «Мои заметки», «Журнал агента» и «Нужно тебе». В личных разделах оставь пустое место, служебные разделы снабди коротким пояснением.

6. Настрой максимально строгий запрет записи в «Я» средствами текущей агентной среды. Сначала прочитай её актуальную локальную документацию и не придумывай синтаксис конфигурации. Если среда не поддерживает надёжный запрет по пути, оставь инструкции в AGENTS.md и отдельно перечисли ручной шаг, который должен выполнить пользователь. Не пытайся обходить ограничения через shell, Python или другой инструмент.

7. Добавь README.md с краткой схемой папок, порядком открытия хранилища в Obsidian, ежедневным сценарием работы и способом полного удаления созданного каркаса.

После выполнения покажи:
- дерево созданных файлов;
- где действует защита от записи;
- какой файл нужно открыть в Obsidian;
- как проверить защиту безопасной тестовой командой;
- что осталось сделать вручную.

Не устанавливай дополнительные программы, не подключай облачные сервисы, не создавай удалённый репозиторий и не публикуй содержимое хранилища.
```

## Карта в корне должна оставаться короткой

Один большой файл с инструкциями быстро обрастает повторами и конфликтами. В рабочем контуре из 67 файлов обнаружились 28 дублей и 29 прямых противоречий. После разделения одно правило стало жить в одном файле, корневая карта сократилась, а 25 локальных инструкций начали подключаться только для нужной папки.

01. **Корень (до 60 строк).** Карта папок, маршрутизация задач и общие запреты.
02. **Папка (до 15 строк).** Локальные правила, формат файлов и разрешённые действия.
03. **Процесс (одна задача).** Инструкция для конкретной повторяемой работы и её находки.

- [ ] В корневом AGENTS.md нет подробностей отдельных процессов.
- [ ] У каждой рабочей папки есть собственный короткий AGENTS.md.
- [ ] Одно правило записано в одном месте.
- [ ] После задачи агент пишет в журнал время, действие и затронутые файлы.
- [ ] Неясное место хранения согласуется с пользователем.
- [ ] Ограничение на запись проверено безопасной тестовой командой.

## Настрой ежедневную точку входа

В Obsidian включи встроенный плагин Daily notes. Укажи папку «Я/Дни», формат даты YYYY-MM-DD и шаблон «Агент/Шаблоны/День». При желании назначь горячую клавишу, например Command+D. Официальная инструкция: https://obsidian.md/help/plugins/daily-notes

| Настройка | Значение |
|---|---|
| Плагин | Daily notes |
| Папка | Я/Дни |
| Формат | YYYY-MM-DD |
| Шаблон | Агент/Шаблоны/День |
| Разделы | Мои заметки / Журнал агента / Нужно тебе |

Личная часть заметки остаётся у человека. Агент дописывает свой журнал и блок с вопросами или задачами. Оба работают в одном дне, сохраняя границу между исходными мыслями и служебными выводами.

## Подключи первый источник данных

Первый сборщик лучше строить на одном официальном API и небольшом наборе показателей. В примере используются подписчики, просмотры, число роликов и просмотры за сутки. Скрипт получает числа без участия модели и записывает только свойства дневной заметки.

## Промпт для сборщика YouTube

```text
Напиши сборщик «Агент/Сборщики/youtube.py» для моего YouTube-канала.

Требования к данным:
- используй только официальный YouTube Data API v3, метод channels.list, part=statistics;
- ключ API и ID канала лежат в .env в корне хранилища; не копируй их в код, журнал, вывод терминала или итоговый отчёт;
- добавь .env в .gitignore;
- никакого ИИ внутри сборщика: только запрос к API, проверка ответа, расчёт разницы и запись чисел.

Каждый запуск:
1. Открой сегодняшнюю дневную заметку «Я/Дни/YYYY-MM-DD.md». Если её нет, создай из шаблона «Агент/Шаблоны/День.md» и подставь сегодняшнюю дату вместо {{date:YYYY-MM-DD}}.
2. Обнови только свойства frontmatter: subscribers, views, videos и views_per_day. Остальное содержимое файла не меняй.
3. views_per_day рассчитай как разницу между текущим views и значением views во вчерашней заметке. Если вчерашней заметки или значения нет, оставь поле пустым и запиши причину в журнал.
4. При ошибке API ничего не меняй в дневной заметке. Запиши безопасное описание ошибки без секретов в «Агент/Журнал/YYYY-MM-DD.md».
5. Рядом со сборщиком создай короткий AGENTS.md: что собирается, откуда, какие поля разрешено менять и когда запускается.

Сначала проверь существующие файлы и покажи план. После моего подтверждения создай сборщик, запусти один раз и покажи только названия записанных полей и их статус без секретов. Затем настрой запуск каждый день в 07:00 по локальному времени и объясни, как проверить расписание. Если компьютер был выключен или спал, задача должна выполниться после следующего включения, если это поддерживается штатным планировщиком ОС.

Если хранилище лежит в «Документах», на Рабочем столе или в облачной папке, сначала предупреди, что фоновой задаче macOS может потребоваться дополнительный доступ. Не запрашивай и не меняй системные разрешения без моего подтверждения. Не устанавливай сторонний планировщик и не используй sudo.
```

- [ ] Ключ API хранится в .env и не попадает в отчёты.
- [ ] Сборщик меняет только разрешённые свойства frontmatter.
- [ ] Первый запуск выполнен вручную и записан в журнал.
- [ ] Ошибочный ответ API не портит дневную заметку.
- [ ] Расписание на 07:00 проверено штатной командой ОС.
- [ ] После сна или выключения предусмотрен отложенный запуск.

## Преврати свойства дневных заметок в таблицу

Obsidian Bases создаёт представления, похожие на базу данных, поверх локальных Markdown-файлов и их свойств. Каждая строка соответствует дневной заметке, каждый столбец — отдельному показателю. Официальная справка: https://obsidian.md/help/bases

## Промпт для базы ежедневных метрик

```text
Создай в «Агент/Таблицы» базу Obsidian для ежедневной аналитики. Перед работой прочитай установленный навык obsidian-bases и текущую официальную документацию формата .base.

Источник данных: Markdown-файлы из «Я/Дни». Одна строка таблицы должна соответствовать одному дню. Покажи колонки date, subscribers, views, views_per_day и videos. Отсортируй записи от новой даты к старой. Пустое значение оставляй пустым, ничего не вычисляй по догадке.

Создай файл «Агент/Таблицы/Ежедневная аналитика.base». Не меняй дневные заметки. Если нужное свойство отсутствует, перечисли файлы и свойства в отчёте, но не дописывай значения самостоятельно.

После создания проверь базу на существующих заметках и покажи:
- путь к файлу .base;
- число найденных дневных заметок;
- список колонок;
- записи с пропущенными данными;
- как открыть базу в Obsidian.

Не добавляй плагины и не публикуй данные.
```

Одна строка показывает только текущее состояние. Через 14 дней становится видна динамика. Если добавить продажи, переходы и подписчиков Telegram, просмотры сайта и другие показатели проекта, таблица начнёт показывать связи между действиями и результатами в одном месте.

## Заведи находки для повторяемых процессов

У каждого повторяемого дела должен быть файл с находками: что сделали, какие цифры получили и какой вывод нужно применить в следующий раз. Агент читает его перед работой и дописывает после появления результата. Так ошибки перестают возвращаться в каждом новом диалоге.

- **исходный процесс: 67 ФАЙЛОВ** - правила копились в разных местах
- **повторы: 28 ДУБЛЕЙ** - одно требование было записано несколько раз
- **конфликты: 29 ПРОТИВОРЕЧИЙ** - агент получал взаимоисключающие команды

В примере с постами рамка «есть первый тип, есть второй тип» встретилась один раз в 2 143 опубликованных постах, при этом ИИ-черновики вставляли её в 77–87% пакетов. Записанная находка позволяет ловить шаблон до выдачи финального текста. В рабочей системе накопилось 194 таких записи.

## Промпт для процесса и файла находок

```text
Заведи процесс «Агент/Процессы/Посты» для подготовки постов в Telegram-канал. Не пиши посты с нуля вместо меня: исходником служит мой текст, расшифровка голосового сообщения или черновик.

Создай AGENTS.md процесса с этапами: получить исходник, выделить главную мысль, собрать черновик, убрать повторы и воду, проверить находки, вернуть финальную версию без изменения фактов.

Добавь два обязательных правила:
- перед каждым постом полностью читать «находки.md»;
- после публикации и получения цифр дописывать новую строку: дата, что сделали, измеримые результаты и вывод для следующего раза.

Создай «находки.md» как таблицу «дата | что сделали | цифры | вывод». Внеси первые три находки:
1. Рамка «есть первый тип… а есть второй тип…» встретилась один раз в 2 143 моих постах, а ИИ-черновики вставляли её в 77–87% пакетов. Не использовать эту рамку без прямого основания в исходнике.
2. Длинное тире «—» воспринимается как шаблонный текст ИИ. В обычной прозе использовать дефис с пробелами « - », если это соответствует исходной манере.
3. Не дробить одну мысль точками на короткие обрубки. Сохранять естественную длину фраз и писать так, как звучит исходная речь.

Проверь, нет ли этих правил в других файлах процесса. Если есть дубль или противоречие, ничего не удаляй: покажи точные пути и предложи один канонический файл. После создания выведи дерево процесса и кратко объясни, когда агент читает и обновляет находки.
```

## Своди контекст в три дела на сегодня

Утренний обзор связывает метрики, журнал, задачи, проекты и находки. На выходе остаются ровно три дела. У каждого есть действие, причина выполнить его сегодня и оценка времени. Если данных недостаточно, агент пишет об этом отдельно и не заполняет пробелы догадками.

| Поле | Что должно быть в задаче |
|---|---|
| Что сделать | одно проверяемое действие |
| Почему сегодня | цифра, срок, зависимость или незакрытый вопрос |
| Сколько займёт | реалистичная оценка времени |

## Промпт для утренних трёх задач

```text
Настрой утренний обзор хранилища. Он должен работать после ежедневных сборщиков и создавать файл «Агент/Нужно тебе/YYYY-MM-DD.md».

Каждый запуск читай:
- сегодняшнюю и вчерашнюю заметки из «Я/Дни»;
- до 14 доступных числовых показателей из свойств дневных заметок;
- записи «Агент/Журнал» за последние 7 дней;
- открытые задачи из «Я/Задачи»;
- актуальный контекст из «Я/Проекты»;
- находки процессов, к которым относятся открытые задачи.

Сформируй ровно три дела на сегодня. Для каждого укажи:
1. Что сделать — одно конкретное действие с проверяемым результатом.
2. Почему именно сегодня — ссылка на файл, срок, зависимость или конкретная цифра, которая подтверждает приоритет.
3. Сколько это займёт — реалистичная оценка времени.

Правила выбора:
- сначала срочные обязательства и задачи, которые блокируют другие действия;
- затем заметные отклонения в метриках и накопившиеся нерешённые вопросы;
- затем задача с наибольшим ожидаемым эффектом, если для неё достаточно данных;
- не придумывай сроки, цифры, связи и приоритеты;
- не меняй файлы в «Я» и не отмечай задачи выполненными;
```
